# ПСБ — юридический ИИ-ассистент (Hack&Change 2026)

Проект содержит два согласованных контура:
1. `solution.py` — автономная точка входа для автоматической проверки. Читает `questions.csv` и `knowledge-base.zip`, создаёт `submission.csv`.
2. `web/` — веб-прототип с тем же поисковым и генеративным конвейером, просмотром исходных документов и карточками подтверждающих фрагментов.

## Архитектура

`ZIP базы → извлечение TXT/MD/DOCX → структурное разбиение → BM25 → dense retrieval (BAAI/bge-m3) → Qwen3 reranker → DeepSeek V4.1 Flash → проверка ID источников → ответ + основания`

### Поиск и обработка документов
- Сохраняются название исходного документа, категория, структурный раздел и ID фрагмента.
- Законы делятся по абзацам и маркерам статей/частей; внутренние документы — по абзацам, с ограничением размера фрагмента.
- Гибридный поиск сочетает BM25 и векторную близость; затем ограниченный набор кандидатов передаётся реранкеру.
- Индекс эмбеддингов строится один раз при запуске и пакетируется, чтобы не отправлять всю базу одним запросом.
- Если эмбеддинги или реранкер недоступны, поиск продолжает работать на BM25; ошибка не маскируется под успешный ответ.

### Контроль достоверности
- В промпт передаются только найденные фрагменты базы. Внешний поиск не используется.
- Содержимое документов помечается как недоверенные данные: найденные в них инструкции не исполняются.
- Модель возвращает структурированный JSON с `answer`, `used_sources`, `insufficient`.
- Ссылки модели сверяются с реальными ID переданных фрагментов. Несуществующие ID не попадают в ответ.
- Источники автоматически прикладываются к ответу с названием документа и найденным разделом.
- При отсутствии подтверждающих фрагментов или некорректном ответе используется безопасное сообщение вместо неподтверждённого юридического вывода.
- История короткого диалога передаётся только из ролей `user` и `assistant`; поддельные `system`-сообщения не принимаются.
- Дата/редакция не угадывается: промпт требует отдельно сообщать, если в базе нет исторической редакции или сведений о вступлении допсоглашения в силу.

> Ограничение: автоматическая проверка источников подтверждает, что ссылка относится к реально найденному фрагменту, но не является формальным доказательством логического следования каждого предложения. Для промышленного применения необходима отдельная оценка entailment/claim-level и юридическая проверка.

## Автоматический сабмит

В каталоге проекта:

```bash
python scripts/build_submission.py
```

Скрипт создаёт `submission.zip` с файлами `solution.py` и `requirements.txt` непосредственно в корне архива — как требует регламент.

Локальный тестовый запуск (в каталоге, где доступны `data/questions.csv` и `data/knowledge-base.zip`):

```bash
pip install -r requirements.txt
python solution.py
```

Результат: `submission.csv`, UTF-8, ровно колонки `id,answer`, одна строка на входной ID, стандартное CSV-экранирование. Ответы ограничиваются 10 000 символами. Входные файлы в ZIP сабмита не включаются.

Переменные окружения платформы:
- `LLM_BASE_URL` и `LLM_API_KEY` (или `OPENAI_BASE_URL`, `OPENAI_API_KEY`);
- `LLM_MODEL` / `GEN_MODEL` / `OPENAI_MODEL` — модель генерации, берётся из окружения;
- `EMB_MODEL` — по умолчанию `BAAI/bge-m3`;
- `RERANKER_MODEL` — по умолчанию `Qwen3-Reranker-8B`;
- `DATA_DIR` — каталог входных данных, по умолчанию `data`;
- `TOP_K`, `RERANKER_TOP_N`, `MAX_WORKERS`, `MAX_TOKENS`.

Секреты не хранятся в исходном коде и не выводятся в логи.

## Веб-прототип

Требуются Docker и Docker Compose. Положите базу знаний в `data/knowledge-base.zip`, скопируйте `.env.example` в `.env` и задайте адрес/ключ доступного OpenAI-совместимого API:

```bash
cp .env.example .env
# заполните LLM_BASE_URL и LLM_API_KEY
docker compose up --build
```

Откройте http://localhost:8000. Интерфейс позволяет:
- задавать вопросы в чате;
- сохранять контекст короткого диалога;
- просматривать список документов и полный текст документа;
- раскрывать фрагменты, использованные в ответе;
- видеть состояние подключения модели.

Без настроенных `LLM_BASE_URL` и `LLM_API_KEY` чат возвращает явную ошибку конфигурации, а не демонстрационный/заранее заготовленный юридический ответ.

Локальный запуск без Docker:

```bash
pip install -r requirements.txt
uvicorn web.app:app --host 0.0.0.0 --port 8000
```

## Структура проекта

```text
solution.py                 # точка входа сабмита и общий RAG-конвейер
requirements.txt            # зафиксированные зависимости
web/app.py                  # API веб-прототипа
web/static/index.html       # интерфейс чата и просмотр источников

tests/                      # локальные проверки
Dockerfile
compose.yaml
.env.example
```

## Проверки перед сдачей

```bash
python -m unittest discover -s tests -v
python scripts/build_submission.py
unzip -l submission.zip
```

Проверьте также один запрос в веб-интерфейсе с тестовым API-ключом и сравните каждый ответ с исходными положениями базы. Состав приватных тестов и golden-ответы организаторов недоступны, поэтому точный итоговый балл заранее гарантировать нельзя.

## Известные ограничения
- Качество зависит от доступности API-эмбеддера и реранкера, корректности идентификаторов моделей и лимитов прокси.
- Сложные таблицы/сканы внутри документов TXT/MD/DOCX требуют отдельного OCR/табличного парсинга; текущий загрузчик работает с текстовым содержимым.
- Историческая редакция закона не восстанавливается из внешних источников; при её отсутствии ассистент должен прямо обозначить пробел.
- Автоматическая оценка достоверности основана на строгом формате и валидации источников, а не на независимом формальном доказательстве каждого тезиса.
